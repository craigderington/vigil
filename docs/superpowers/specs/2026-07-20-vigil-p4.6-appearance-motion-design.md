# Vigil P4.6 — Accent Theming + Motion Polish — Design Spec

> The last P4 slice (CLAUDE.md §14 "full motion + polish + accent theming"; §11.8 "appearance
> (theme + accent-color picker)"; §11.1 tokens + motion). Three cohesive pieces: an **accent
> preset picker** (the `appearance.accent` setting is already backend-plumbed but frontend-dead),
> the one missing spec motion item (**number count-up**), and **panel exit transitions**. All
> user-confirmed via brainstorming: curated presets, dark-only (no light mode), count-up + panel
> exit, **zero new dependencies**, `prefers-reduced-motion` honored throughout.

---

## 1. Goals & Non-Goals

**Goals**
- **Accent picker:** a Settings → Appearance section of curated preset swatches that **applies live**
  and **persists**, correctly recoloring everything that derives from the accent (buttons incl. their
  foreground, chips, focus ring, rail marks), with **no flash** of the wrong accent on reload.
- **Motion:** build the one un-built spec motion item — a **number count-up** on the detail panel's
  response-time hero — and add **graceful exit transitions** for the slide-over panels (they snap
  shut today).
- **Zero new dependencies**; hand-rolled, matching the frontend's lean convention.

**Non-Goals (v1)** (all user-confirmed)
- **No light mode** — the app stays a single dark-navy palette. "Theme" = accent-swapping only. A
  real light theme (a second full token set) is a separate future project.
- **No free color picker** — curated presets only (each ships a contrast-tuned token set; a free
  picker would need runtime contrast math).
- **Count-up scoped** to the response-time hero (§11.6 #2), not every number.
- No new motion beyond count-up + panel exit (no broad micro-interaction sweep).

## 2. Context — what exists / what's the gap

Verified against the tree (P4.6 audit).
- **Accent is backend-wired, frontend-dead.** `GET /api/settings` returns `accent` (default `#3FC8E4`,
  key `appearance.accent`; `api/settings.rs:29`); `UpdateSettingsDto.accent` persists it
  (`api/settings.rs:47,84`). The TS `Settings` interface has `accent: string`. **But nothing on the
  client reads or applies it** — no `setProperty('--accent', …)` anywhere, no picker in `Settings.tsx`,
  and `getSettings()` is only fetched when the Settings screen mounts (never at boot).
- **`--accent` blast radius + gotcha** (`theme.css:6`): `--accent:#3FC8E4; --accent-weak:rgba(63,200,228,0.14);
  --focus-ring:#3FC8E4;`. `var(--accent)` is used at ~7 sites (btn-accent, chip-pressed, rail-mark,
  rail-active, layout-btn-pressed, sort-arrow, btn-link); `--accent-weak` (2), `--focus-ring` (3).
  **`--accent-weak` and `--focus-ring` are hardcoded literals, NOT derived from `--accent`** — a swap
  must set all three. **`.btn-accent{color:#04222b}`** (`theme.css:79`) is a hardcoded dark foreground
  that assumes a cyan background — it won't stay legible on yellow.
- **Motion already implemented:** panel slide-in (`.detail-panel` `panel-slide-in 260ms
  cubic-bezier(0.32,0.72,0,1)`, `theme.css:210`), backdrop fade-in (`backdrop-fade 200ms`, `:202`),
  card hover (`120ms`, `:104`), status-dot `breathe-up`, rail down-count `pulse-text`. **Missing:**
  number count-up (grepped — none). **Panels have no exit animation** — `<Show when={openMonitor()}>`
  (`App.tsx:144`) unmounts instantly, so close snaps. `MonitorForm` reuses `.detail-panel`/`.detail-backdrop`
  so it inherits the same enter-only behavior.
- **`prefers-reduced-motion`:** `theme.css:149-153` near-zeros all transitions/animations
  (`*{transition-duration:0.001ms!important;animation-duration:0.001ms!important}`) + kills the two
  infinite loops. **A JS `requestAnimationFrame` tween is NOT covered by that CSS rule** — the
  count-up must self-check `matchMedia('(prefers-reduced-motion: reduce)')` (the `ResponseChart.tsx:28`
  pattern).
- **App entry** (`index.tsx`): `import "./theme.css"; render(() => <App/>, #root)` — no pre-paint
  script. Applying the accent **before `render()`** overrides the `:root` vars before first paint.
- **Settings section pattern** (`Settings.tsx`): `<section class="form-section settings-section">` +
  `<h3 class="form-section-title">` + fields + a `btn-accent` Save + a `<Show>`-gated "Saved."; one
  `onMount` loads all settings. Existing helper classes `.settings-section`/`.settings-note` exist.

## 3. Accent presets

### 3.1 `web/src/accent.ts` (new)
```ts
export type AccentId = "cyan" | "the-open-yellow" | "magenta" | "teal";
export interface AccentPreset { id: AccentId; name: string; accent: string; accentWeak: string; focusRing: string; accentFg: string; }
export const ACCENT_PRESETS: AccentPreset[] = [
  { id: "cyan",            name: "Cyan",   accent: "#3FC8E4", accentWeak: "rgba(63,200,228,0.14)",  focusRing: "#3FC8E4", accentFg: "#04222b" },
  { id: "the-open-yellow", name: "Yellow", accent: "#FFBA00", accentWeak: "rgba(255,186,0,0.14)",   focusRing: "#FFBA00", accentFg: "#241a02" },
  { id: "magenta",         name: "Magenta",accent: "#E879C9", accentWeak: "rgba(232,121,201,0.16)", focusRing: "#E879C9", accentFg: "#2a0a22" },
  { id: "teal",            name: "Teal",   accent: "#2DD4BF", accentWeak: "rgba(45,212,191,0.16)",  focusRing: "#2DD4BF", accentFg: "#04231f" },
];
export const DEFAULT_ACCENT: AccentId = "cyan";
const KEY = "vigil.accent";
export function presetById(id: string | null | undefined): AccentPreset { /* id match → else legacy-hex match (e.g. "#3FC8E4"→cyan) → else DEFAULT */ }
export function applyAccent(id: string): void { /* p = presetById(id); set --accent/--accent-weak/--focus-ring/--accent-fg on document.documentElement.style; localStorage[KEY]=p.id */ }
export function storedAccentId(): AccentId { /* presetById(localStorage[KEY]).id */ }
```
- Accents are all **non-status colors** (§11.1's rule: accent ≠ green/red/amber/violet/blue/grey status
  colors). The set is tunable; final swatches eyeballed on navy in the live check.
- `presetById` is tolerant: accepts a preset id, a legacy/default hex (`#3FC8E4` → cyan), or unknown →
  `DEFAULT_ACCENT`. This lets the backend keep its `#3FC8E4` default with no backend change.

### 3.2 `theme.css` — one new token + wiring
- Add `--accent-fg:#04222b;` to `:root`. Change `.btn-accent{…color:#04222b}` → `color:var(--accent-fg)`.
  (Everything else — chips, rail marks, focus rings, sort-arrow, btn-link — already reads
  `var(--accent)`/`var(--accent-weak)`/`var(--focus-ring)`, so setting those three at runtime recolors
  them.) No other CSS change for the swap.

### 3.3 No-flash boot (`index.tsx`)
```ts
import "./theme.css";
import { applyAccent, storedAccentId } from "./accent";
applyAccent(storedAccentId());   // BEFORE render → first paint uses the persisted accent
render(() => <App/>, document.getElementById("root")!);
```
On very first load (empty localStorage) it applies `cyan` = the `:root` defaults (no visible change).

### 3.4 Settings → "Appearance" section
- A new `<section class="form-section settings-section">` in `Settings.tsx`: `<h3>Appearance</h3>`, a
  short note, and a row of **swatch buttons** (one per preset). Each swatch shows the accent color and
  its name; the active one is marked (`aria-pressed`). Clicking a swatch: `applyAccent(id)` (live,
  instant) **and** `api.updateSettings({ accent: id })` (persist). A brief "Saved." via the existing
  `<Show>` pattern.
- `onMount` reads `s.accent` and sets the selected signal via `presetById(s.accent).id` (reconciles
  the server value with what boot already applied from localStorage; if they differ, re-apply the
  server value so cross-device/edited state wins).
- **Accessibility:** swatches are `<button>`s with `aria-pressed` + an accessible label ("Cyan
  accent"); the group is a labelled `role="group"`. Focus ring uses the (now-swapping) `--focus-ring`.

### 3.5 Backend
- **No code change** — the setting already round-trips. Add a small assertion to the existing
  `crates/vigil/tests/settings.rs` round-trip test: `accent` defaults to `#3FC8E4` and a PUT of a new
  value round-trips (closes the current coverage gap).

## 4. Number count-up (§11.1 / §11.6 #2)

- **`web/src/motion.ts` (new):** a pure easing helper `easeOutCubic(t)` and a tiny `countUp` primitive
  — a Solid helper `createCountUp(target: () => number | null, ms = 320)` returning an accessor that
  tweens from the **previous** displayed value to the new `target` over `ms` via `requestAnimationFrame`,
  ease-out. **Reduced-motion:** if `matchMedia('(prefers-reduced-motion: reduce)').matches`, it returns
  the target instantly (no rAF). `null` target → renders "—" (no tween). Cleans up its rAF on
  dispose/retarget.
- **Applied** to the detail panel's response-time hero (the "Now strip" response tile, `DetailPanel.tsx`
  §11.6 #2 — "current response time (mono, count-up)"). The displayed integer counts up to the live
  value; subsequent SSE updates tween from the last shown value to the new one.
- **Testability:** `easeOutCubic` + the "reduced-motion → instant final value" and "null → —" branches
  are unit-tested; the rAF timing itself is live-verified (jsdom rAF timing is unreliable).

## 5. Panel exit transitions (hand-rolled, zero deps)

- **`web/src/motion.ts`: `createExitTransition(open: () => boolean, ms = 260)`** → `{ mounted: () =>
  boolean, closing: () => boolean }`. When `open()` flips true → `mounted=true, closing=false`. When it
  flips false → `closing=true` and, after `ms`, `mounted=false` (via `setTimeout`, cleared on
  re-open/dispose). **Reduced-motion → `ms` treated as 0** (instant unmount, matching the CSS rule).
- **`theme.css`:** reverse keyframes `panel-slide-out` (`translateX(0)`→`translateX(100%)`) and
  `backdrop-fade-out` (opacity 1→0); `.detail-panel.closing{animation:panel-slide-out 260ms
  cubic-bezier(0.32,0.72,0,1) forwards}` and `.detail-backdrop.closing{animation:backdrop-fade-out
  200ms ease-out forwards}`. The `@media (prefers-reduced-motion)` block already near-zeros these.
- **`App.tsx` wiring:** replace `<Show when={openMonitor()}>` with the exit-transition lifecycle —
  keep `DetailPanel` mounted while `mounted()` is true, pass `closing={closing()}` so it adds the
  `.closing` class to its backdrop+panel. The panel's own ✕/Esc/backdrop-click still call `onClose`
  (which flips `openMonitorId` to null → drives `open()` false → triggers the exit). Same treatment
  for the **add/edit `MonitorForm`** (`formOpen()` → its own exit transition). `DetailPanel`/`MonitorForm`
  gain an optional `closing?: boolean` prop that toggles the class; enter animations unchanged.
- **Panel content during close:** the detail panel reads `openMonitor()` — which becomes `undefined`
  once `openMonitorId` is null. To avoid the content blanking mid-slide-out, the exit-transition keeps
  the **last** monitor rendered during `closing` (App passes the retained monitor while closing).

## 7. Testing

- **`accent.test.ts`:** `presetById` resolves a preset id, a legacy hex (`#3FC8E4`→cyan), and unknown→
  default; `applyAccent` sets all four CSS vars on `document.documentElement` (assert
  `style.getPropertyValue('--accent'|'--accent-weak'|'--focus-ring'|'--accent-fg')`) and writes
  `localStorage['vigil.accent']`; `storedAccentId` reads it back.
- **`motion.test.ts`:** `easeOutCubic(0)===0`, `(1)===1`, monotonic; `createCountUp` with reduced-motion
  stubbed (`matchMedia` returns `matches:true`) returns the target **instantly**; `null` target → the
  "—" sentinel; `createExitTransition` with `ms=0`/reduced-motion unmounts synchronously, and (fake
  timers) `open→close` keeps `mounted` true + `closing` true until `ms`, then `mounted` false.
- **`settings.test.tsx` (or accent-focused):** clicking a swatch PUTs `{accent:"the-open-yellow"}` and
  sets `--accent` on the root (stub `matchMedia`/`localStorage` as needed).
- **Backend `settings.rs`:** accent default `#3FC8E4` + PUT round-trip.
- **Live (jsdom can't do rAF timing / real CSS animation):** in a real browser — pick each accent
  swatch and confirm buttons/chips/focus-ring/rail recolor with correct contrast; **reload** and
  confirm **no cyan flash** before the chosen accent; watch the response-time **count-up**; **close a
  panel** and see it **slide out** (not snap); toggle OS reduced-motion and confirm instant states.
- Frontend gate: `npx vitest run` + **`npx tsc --noEmit`** (note: `npm run build` is vite-only, does
  NOT typecheck). Backend: `cargo test -p vigil -- --test-threads=1`.

## 8. Documented boundaries (recap)
- **Accent-only**, dark navy stays; **curated presets** (contrast pre-tuned via `--accent-fg`), not a
  free picker; **no light mode**.
- Swap sets **all four** vars (`--accent`/`--accent-weak`/`--focus-ring`/`--accent-fg`) — the weak/focus
  literals aren't derived. Legacy default hex maps to `cyan`; **no backend change** (setting already
  plumbed).
- **No-flash** via localStorage-applied-before-render; Settings reconciles with the server value on
  mount.
- **Count-up** only on the response-time hero; **reduced-motion honored in JS** (rAF self-checks, CSS
  `*` rule doesn't cover it). **Panel exit** hand-rolled (delayed unmount + reverse keyframes), instant
  under reduced-motion; last-monitor retained during close so content doesn't blank.
- **Zero new deps / migration / SSE event / backend source change.**
